# 标准知识库语料（canonical corpus）

本目录是**演示与评测使用的唯一语料来源**，纳入版本管理，保证评测可复现。

## 为什么单独建这个目录

历史上知识库是被测试脚本"顺手上传"的文件填满的：`testing.md`、`decisions.md`
这些项目自己的文档被重复上传且从不清理，导致 Chroma 的 47 个 chunk 里 39 个（83%）
与业务无关，评测数字失去意义。详见 `docs/review-v1-audit.md` §2.5。

现在规则很明确：

- **要进知识库的语料放在本目录**，由 `scripts/rebuild_kb.py` 统一灌入；
- **测试上传的文件落在临时目录**（pytest 的 `tmp_path`），用完即弃，不污染语料；
- `data/documents/` 是运行时的上传落盘目录，已被 `.gitignore` 忽略。

## 当前语料（6 个文档）

**故意包含 2 个近邻干扰文档**：它们在"年假 / 住宿 / 考勤"话题上会被检索命中，
但关键数值一律"以《员工考勤制度》为准"，从而迫使检索真正认准出处 ——
否则只有一两个文档时，`source_accuracy` 是"必然命中"，没有区分度。

| 文件 | 角色 | 被评测引用的题数 |
| --- | --- | --- |
| `员工考勤制度.txt` | 核心制度（年假 / 住宿标准 / 交通费 / 餐补 / 工时） | 19 |
| `员工福利制度.docx` | 补充福利（团建 / 体检 / 生日），同时验证 DOCX 解析链路 | 4 |
| `员工培训管理制度.txt` | 独立制度（入职培训 / 考核 / 费用 / 外部培训） | 4 |
| `办公用品与设备管理办法.txt` | 独立制度（领用 / 盘点 / 审批 / 固定资产） | 4 |
| `差旅与报销指引.txt` | **近邻干扰**：谈出差、住宿、交通费，但让位给《员工考勤制度》 | 4（报销时限 / 审批 / 票据 / 超支自担） |
| `新员工入职指引.txt` | **近邻干扰**：谈年假、考勤，同样让位给《员工考勤制度》 | 4（试用期 / 入职材料 / 转正） |

## 重建方式

```powershell
.venv\Scripts\python scripts\rebuild_kb.py --dry-run   # 先看会删什么
.venv\Scripts\python scripts\rebuild_kb.py             # 执行（自动备份到 data/backups/）
```

## 新增/修改语料时的硬约束（已固化为测试）

1. **测试集里的 `expected_source_doc` 必须与这里的文件名完全一致**，否则来源准确率必然掉；
2. 新增文档后，**至少有一条题引用它**（否则它进不了检索路径，等于白灌）；
3. `gold_evidence` 必须能在对应文件里**逐句找到**，不允许凭空编造事实；
4. 改完必须**重建索引**，否则新文档不在库里。

> 以上 4 条由 `tests/test_evaluation.py` 的一致性用例守住（见 `docs/testing.md` §5/§6.1）。
> 想加语料：把文件丢进本目录 → 在 `data/evaluation/test_set_smart.json` 里加题 → `rebuild_kb.py` → 跑 pytest。
