# 项目复盘（Retrospective）

> 本文档用于项目总结与面试复述，记录"做了什么、踩了什么坑、收获与不足"。

## 1. 项目概述

企业级 RAG + Agent 智能知识库系统：面向 HR / 行政 / 客服，上传制度文档，得到"答得准、可溯源、不知道就拒答"的内部 AI 助手。

技术栈：FastAPI · MySQL · Chroma · bge-small-zh · DeepSeek · JWT · ReAct。

## 2. 交付内容

- **P0**：RAG 全链路、Router 三路分发、Agent + 工具调用、登录鉴权、评测、MySQL；
- **P1**：DOCX 解析、多轮对话、评测可视化、Rerank A/B。

## 3. 关键问题与解决

1. **ReAct 解析对格式敏感**：真实 LLM 有时把最终答案直接写在 `Action: Final Answer` 后面、没有 `Action Input:` 行，导致答案里混进 `Thought/Action` 中间格式 → 重写 `_parse`，优先整段提取 Final Answer 后的内容。
2. **LLM 偶发空返回**：真实 API 偶尔返回空 content，导致 Agent 答案为空 → 在 LLM 客户端加空返回自动重试（最多 3 次）。
3. **Rerank 是否有用？** 不预设答案，做 A/B：Noop vs bge-reranker-base。结果持平——定位到原因是"单文档单 chunk，重排无发挥空间"，因此按数据保持关闭。

## 4. 结果数据（真实）

| 项 | 结果 |
| --- | --- |
| RAG 问答 | 带引用正确回答 |
| 拒答 | 正确拒答 |
| Router | 三路分类正确 |
| Agent 计算 | 100 * 1.08 = 108 |
| 评测（5 题） | 关键词 100% · 来源 100% · 拒答 100% · 综合 100% |

## 5. 收获

- **真实环境验证 > mock**：两个关键 bug 都只在真实 LLM 下暴露，mock 永远测不出来；
- **数据驱动决策**：Rerank 用 A/B 说话，而不是"听说要用"；
- **范围控制**：P0/P1/P2 + Change Log 机制，避免了需求膨胀；
- **工程规范**：复用审计、ADR、测试脚本、文档体系。

## 6. 不足与改进

- 评测测试集偏小（5 题），结论代表性有限，需扩展到更大规模；
- Rerank 未在"多文档多 chunk"语料上验证，结论不完整；
- 无流式输出，长回答体验一般（V2）；
- 单租户、无权限隔离（V2）。

## 7. 下一步（V2）

OCR（扫描件）· Excel 解析 · 流式输出（SSE）· MCP · 多租户与 RBAC · 更大语料 Rerank 重测。
